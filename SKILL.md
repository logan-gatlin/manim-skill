# Manim

Installed here: **Manim Community v0.22.1** (`manim` on PATH, a `uv tool` install with the `typst` extra), plus TeX Live and `dvisvgm` for `Tex`/`MathTex`, and Chatterbox Turbo for narration (a CPU install in its own venv under `~/.local/opt/chatterbox`, driven by `narration.py`). Scene files run on the tool's own Python, which includes `numpy`, `scipy` and `networkx`; other imports fail. Use the ManimCE API only. 3Blue1Brown's `manimgl` is a different library, so code written for it won't run here.

## Style

Manim is a tool for presenting information in a dynamic and interesting way.
If what you made could just as easily have been made as a flowchart, spreadsheet, dot graph, or slideshow, you are not correctly using manim.
Beautiful is more engaging, and more memorable.
Avoid technical jargon, keep your presentation accessible.
Pick a set of motifs and stick to them - a concept should have a consistent visual representation.
Tell a story, start in media res.
Introduce ideas and problems from first principles

## Steps

1. **Pick the output.** Use a still PNG for a static picture (a labeled diagram, plot, table or formula). Use an MP4 when the point is change or sequence (a derivation step by step, a moving point, a transform). Use GIF only when the place it's going can't play video.
2. **Find the closest examples.** Open the topic file(s) below, scan the index at the top, and read the 1–3 examples closest to what you need. Build your scene by adapting them: their API usage is known to work on this version.
3. **Write the scene** to `/tmp/manim/<slug>/scene.py` unless the user named a location. Start it with `from manim import *` and define one `Scene` subclass (`MovingCameraScene` / `ThreeDScene` / `ZoomedScene` when the examples use one).

   Every picture of a thing (a cloud, a server, a padlock, a flag, a person, a document) is an **icon** from this skill's library, used as it is: copy [icons.py](icons.py) next to the scene, find an id with `grep -iw <word> assets/index.tsv` in this skill's directory (try a synonym when a word finds nothing), and load it with `icon(id, color=..., height=...)`. `tabler/outline/*` and `tabler/filled/*` are one-color line and solid icons (Tabler Icons) drawn in `color`; `fluent/*` are full-color emoji (Fluent Emoji, Flat style) that keep their own colors. Draw only the diagram's structure yourself, from Manim's shapes: boxes, arrows, lines, axes, plots and labels. Give each concept one icon and reuse it, as one of the motifs.

   Code on screen is set in **JetBrains Mono**, which this skill carries in `assets/fonts/`, so it looks the same on every machine. Copy [code_font.py](code_font.py) next to the scene and `import code_font` before building any text: every `Code` block then uses the font with no further setting. For code written with `Text` (a command, a file name, an identifier), use `from code_font import MONO` and pass `font=MONO`.

   Before drawing a common piece yourself, check [components/](components/) for a ready-made one: each folder holds a module to copy next to the scene, a README with the API and example images. [components/progress/](components/progress/README.md) has live progress indicators (a ring, a liquid-filled tube, a stepper of named stages, a bar of named phases, a box that fills with squares) that redraw from a `ValueTracker` and celebrate on reaching 100%. [components/git/](components/git/README.md) draws a Git history you drive with Git operations (commit, branch, checkout, merge, rebase, cherry-pick, revert, reset, amend, tag), animating each change. [components/node/](components/node/README.md) is the box for one thing in an architecture diagram (a service, a database, a client): a card with an icon, a name and a second line, whose bar changes color with its status (inactive, active, failed). [components/boundary/](components/boundary/README.md) draws a labelled outline around a group of nodes (a network, a cluster, a region), which widens and closes up as members join and leave. [components/line/](components/line/README.md) is the one line for connecting things: an arrow routed straight or in elbows, with options for dashes or dots, two-way tips, a label, forks and U-turns, and an entrance that draws it in tip first. [components/packet/](components/packet/README.md) sends packets along such a line: one comet, or a burst, some of which can be dropped part-way, with the arrow's tip swelling as each lands. [components/sequence/](components/sequence/README.md) is a sequence diagram: names across the top with a lifeline each, and requests, replies, failures and lost messages drawn between them one row at a time. [components/queue/](components/queue/README.md) is a queue between brackets: items join, wait their turn and leave, and when it is full the brackets turn red and newcomers wait outside. [components/states/](components/states/README.md) is a state machine: states as chips with the current one filled, joined by labelled arrows that route themselves and light up as each transition fires. [components/chart/](components/chart/README.md) is a live chart: one metric as a scrolling line with its reading at the head, red wherever it is over a threshold. [components/terminal/](components/terminal/README.md) is a terminal: commands typed at a prompt a character at a time, and their output arriving line by line, scrolling when it fills. [components/table/](components/table/README.md) is a table of records: rows are inserted, updated and deleted, each change marked by a colored bar at the left of its row while the row opens, its values slide over or it closes up. [components/tree/](components/tree/README.md) is a tree (a binary search tree, or any hierarchy): values on chips joined by elbow lines, where nodes are added and removed, a search lights the nodes it passes, branches fold away, and the rest of the tree moves over to make room. [components/callout/](components/callout/README.md) is a callout: a short label joined to a mobject or a point by a thin line that turns once, drawn in from the thing it describes, for annotating a diagram. [components/browser/](components/browser/README.md) is a browser window to put an interface inside: a panel with an address bar and a screen area that pages are fitted to, where going to another address slides the address over, runs a loading bar and swaps the page. [components/funnel/](components/funnel/README.md) is a funnel that dots flow through, thinning out at each stage. [components/timeline/](components/timeline/README.md) is a timeline of rows whose bars fill as a time cursor passes, for work in sequence, overlapping, or stopping and starting. [components/log/](components/log/README.md) is a run log whose steps spin while they run and get a check when done. [components/clock/](components/clock/README.md) is an analog clock with the time in 24-hour digits below it and, optionally, the weekday, date and time zone, which turns forwards or backwards to another time with its hands spinning and its digits turning over on wheels.

   An MP4 or GIF that shows text must give viewers **reading time**, and a checker enforces it. Copy [reading_time.py](reading_time.py) next to the scene, import it with `from reading_time import ReadingTime`, and put the mixin before the scene base class: `class SceneName(ReadingTime, Scene)`. Call `self.wait_to_read()` before every `play` that hides, replaces or dims text. It holds until each visible text has been on screen for 1 s plus its words at 150 wpm, with all text revealed by one `play` read together. Show new words as a new mobject (`FadeIn`, `ReplacementTransform`) rather than with `become()`, so that its time starts fresh. Motion can keep running during the hold: put `self.wait_to_read()` after an animation that plays while the text is up.

   An MP4 that explains in captions is also **narrated**: a voice reads it out. Copy [narration.py](narration.py) next to the scene and put it before `ReadingTime`: `class SceneName(Narration, ReadingTime, Scene)`. `self.speak(text)` waits for the previous line to finish, then starts the next one, and the animations that follow play while it's spoken. Put it right before the `play` that shows the caption it reads. The caption shows the spoken line word for word, and every spoken line has one: write each line once and pass that same string to `speak` and to the caption's `Text`. When the voice needs a respelling the screen doesn't ("twenty" for "20"), put it in the scene's `pronounce` dict, which changes only what is voiced. In a narrated scene the voice sets the hold instead of the word count: text that appears while a line is spoken must stay until the narrator finishes plus a 0.5 s pause, and `self.wait_to_read()` holds exactly that long before the next change (text shown during silence keeps the word-count rule). The voice is a neural clone of a calm male narrator (Chatterbox Turbo), tuned for walking through technical diagrams. Each new line takes about 1–3× its spoken length to synthesize, draft stills included, and is cached under `media/voice`, so later renders only voice the lines you changed. Write each line to be heard, not read. Acronyms such as API, TLS and HTTP read well as written, and `narration.py` already spells out units after numbers (`200 ms`), dotted versions (`2.4.1`) and `k8s`. Say other machine strings the way a narrator would, again through `pronounce`: "seventeen eleven", not "2026.11.1711". Describe paths and branch names rather than reading them out ("an auto patches release branch"), and fix any word the voice gets wrong through the scene's `pronounce` dict (`{"edgeworker": "edge worker"}`).

   Every MP4 or GIF ends on a **credit card** naming the model that made it. Copy [produced_by.py](produced_by.py) next to the scene, put the mixin first of all: `class SceneName(ProducedBy, Narration, ReadingTime, Scene)` (or `class SceneName(ProducedBy, Scene)` for a scene without text), and set `produced_by` to your own model name as your system prompt gives it (`produced_by = "Claude Opus 5.5"`). If your instructions don't name your model, ask the user. Once the scene, its narration and its reading-time check have finished, the mixin fades the scene out and holds the card for the last 0.5 s. Still renders skip it.
4. **Draft and look.** Render a low-quality still and read the PNG:
   ```bash
   cd /tmp/manim/<slug> && manim render -ql -s --media_dir media -o draft scene.py SceneName
   # -> media/images/scene/draft.png
   ```
   For an animation, also check key moments: `-s -n 0,K` stops after animation `K` (0-based; each `self.play` and each `self.wait` counts as one) and saves that frame. The frame is about 14.2 × 8 units, centred on the origin. Fix and re-render until every frame you checked shows all elements inside the frame, no overlapping labels, and readable text.

   A scene that takes text away too soon fails with `ReadingTimeError`, which lists each text, when it appeared, and how long it was shown against how long it needed. Add `self.wait_to_read()` before each listed change. To look at draft frames before the timing is fixed, prefix the command with `MANIM_READING_TIME=warn`. The final render runs without it and must pass.
5. **Final render.** Use `-qh --fps 30` (1080p at 30 fps). Render time grows with the number of frames, not with the resolution, so 60 fps would double the wait. 3D scenes are slow on the Cairo renderer, so draft them at `-ql`.
   ```bash
   manim render -qh --fps 30 --media_dir media -o final scene.py SceneName
   # -> media/videos/scene/1080p30/final.mp4   (add --format gif for a GIF; -s for a PNG at media/images/scene/final.png)
   ```

   **Render several videos at the same time.** One render uses one CPU core, so start a render for each video, up to `nproc` of them at once, and wait for them all:
   ```bash
   render() { (cd /tmp/manim/$1 && manim render -qh --fps 30 --media_dir media -o $1-v2 scene.py $2 < /dev/null > render.log 2>&1 \
     || echo "FAILED: $1, see /tmp/manim/$1/render.log"); }
   render intro Intro & render flow Flow & render outro Outro & wait
   ```
   A render that fails prints `FAILED` and leaves its error in `render.log`. Keep the `< /dev/null`: without it, a misspelled scene name makes Manim wait for an answer that never comes. Renders that run at the same time each need their own `--media_dir`: two that share one overwrite each other's files and fail. Scenes in separate directories, as above, already have one each. When several scenes share a directory, give each scene `--media_dir media-<SceneName>` in its drafts and its final alike.
6. **Deliver.** Show the output inline when your interface can display it, which is when your instructions say Markdown image syntax embeds images or video (T3 Code's do). Copy the output file into the session's working directory, then embed it from there with its absolute path (`![title](/abs/path/out.mp4)`; this works for MP4 and PNG alike). T3 Code renders media inline only from the working directory, so an embed pointing into `/tmp` shows up as a plain link. In an interface that shows only text, such as a plain terminal, give the output file's absolute path instead. Either way, also give the scene file path so the user can tweak it.

   **Every iteration ends in a delivery.** Whenever you change a scene, whether for the user's feedback or for your own fixes, finish the turn by delivering every video in the set at final quality as in step 6, even the ones you didn't touch. Re-render only the videos whose scene changed, or whose scene imports a file that changed (a helper, a component). For each of the others, copy the last round's video to this round's name (`cp intro-v2.mp4 intro-v3.mp4`) rather than rendering it again, since it would come out the same. Stills and frame grabs help you check your work, but they don't replace the videos. Give each round its own file names (`<name>-v2.mp4`, `<name>-v3.mp4`), so earlier messages keep showing the versions they described.

## Looking up the API

The installed source, with full docstrings, is at `~/.local/share/uv/tools/manim/lib/python3.13/site-packages/manim/`. Grep it for a class or method's signature and options before guessing a keyword argument.

## Gotchas

- Write LaTeX strings as raw strings (`r"\frac{a}{b}"`). A LaTeX error prints the `.tex` log, and the offending line is usually near the end.
- `xelatex` is not installed, so `TexTemplateLibrary` templates that need it (e.g. `ctex`) fail. For CJK text use `Text`/`MarkupText`, which render through Pango with system fonts (`fc-list` shows them).
- `Typst` / `MathTypst` are a faster alternative to `Tex` / `MathTex` and need no LaTeX.
- Load icons with `icon()`, which recolors Tabler icons: their files draw in `currentColor`, which a plain `SVGMobject` reads as black.
- Fluent icons drawn in black (`fluent/black-flag`, `fluent/black-cat`) vanish on the black background; pick another icon, or set it on a light shape.
- Tabler line icons lose dots drawn as zero-length lines, such as the lights on `tabler/outline/server`.
